# Course Architecture

## Introduction
Courses on this platform are NOT collections of videos or traditional "Chapter 1, Chapter 2" formats. They are structured, project-based journeys designed to build mastery incrementally.

## Course Hierarchy
Every course must adhere to the following structural hierarchy:

1. **Course:** The overarching subject (e.g., "Web Creator Foundations").
2. **Modules:** Major thematic sections within the course (e.g., "Foundations", "Skill Modules", "Mini Projects").
3. **Units:** Specific topical groupings within a module.
4. **Lessons:** The individual learning units (Why it matters → Concept → Explanation → Demonstration).
5. **Concepts:** The granular ideas taught within a lesson.
6. **Practice:** Interactive exercises immediately following a concept.
7. **Challenges:** Problems requiring independent application of concepts.
8. **Projects:** Tangible outputs where multiple concepts are combined.
9. **Milestones:** Checkpoints within larger projects.
10. **Assessments:** Formal evaluations of mastery.
11. **Capstone:** The final demonstration project for the course.

## Course Definition Requirements
When designing a new course, the following elements MUST be explicitly defined:

- **Prerequisites:** What must the student know or have completed before starting?
- **Learning Outcomes:** What specific capabilities will the student possess upon completion?
- **Skills:** The granular technical and soft skills developed.
- **Projects:** The specific applications, websites, or programs the student will build.
- **Assessments:** How we will objectively measure mastery.
- **Mastery Criteria:** The threshold a student must reach to be considered "competent".
- **Portfolio Output:** What exactly will be added to the student's public portfolio at the end of this course.

## The Project System
Projects are the core of the course architecture. 
- Projects are built feature-by-feature (e.g., Feature 1: Create project → Feature 2: Add navigation → Feature 3: Add database).
- Projects must be rooted in real-world contexts (e.g., a school management app, a local business website), not just artificial tutorial examples.
