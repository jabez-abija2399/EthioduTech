# Final Project Requirements

## 🎯 What You Must Demonstrate

To graduate, you must demonstrate that you can **independently build, understand, debug, improve, document, deploy, and explain** a complete responsive website.

This is not a new project—it is the **mature version** of the same project you have been building throughout the course.

---

## ✅ Technical Requirements

### HTML

- Valid HTML5 structure
- Semantic elements used correctly (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`)
- Proper heading hierarchy (`<h1>` to `<h6>`)
- Forms with appropriate input types and labels
- Alt text for all images
- No major validation errors

### CSS

- External stylesheet linked correctly
- Consistent color system and typography
- Flexbox and/or Grid used for layouts
- Responsive design (mobile-first or adaptive)
- CSS variables for theming (optional but recommended)
- No major styling issues

### JavaScript

- External script linked correctly
- Variables declared with `let` or `const`
- Functions used appropriately
- DOM manipulation (selecting, changing, creating elements)
- Event handling (click, input, submit, etc.)
- No console errors

### Data & APIs

- JSON data used appropriately
- localStorage feature implemented (e.g., save user preferences)
- Fetch API used to retrieve data from at least one public API
- Loading, error, and success states handled

### Accessibility

- Keyboard navigation works (tab through all interactive elements)
- Focus styles visible
- Alt text for images
- Labels for form inputs
- Sufficient color contrast
- Semantic structure supports screen readers

### SEO

- Unique, descriptive `<title>` for each page
- Meta description present
- Proper heading hierarchy
- Descriptive link text
- Image file names and alt text optimized
- Open Graph metadata for social sharing (optional)

### Performance

- Images optimized (appropriate formats, compressed)
- Lazy loading for images below the fold
- Minimal unnecessary JavaScript
- No large, unused CSS or JS files
- Core Web Vitals scores acceptable (LCP, CLS, INP)

### Security

- User input validated and sanitized
- No unsafe `innerHTML` with untrusted data
- HTTPS used (via deployment platform)
- No exposed secrets or API keys in frontend code

## 📁 Project Structure

Your final project must follow this structure:

```
your-business-website/
├── index.html
├── about.html (optional)
├── css/
│   └── styles.css
├── js/
│   └── main.js
├── images/
│   ├── logo.png
│   ├── hero.jpg
│   └── ...
├── data/
│   └── business.json (optional)
└── README.md
```

## 📝 Documentation Requirements

### README.md

Your README must include:

- Project title and description
- Business name and description
- Features list
- Technologies used
- Setup instructions (how to run locally)
- Deployment URL
- Screenshots (optional)
- Credits (images, APIs, etc.)

---

## 🚀 Deployment

Your project must be **deployed to the internet** and accessible via a public URL.

Recommended platforms:

- GitHub Pages (free)
- Netlify (free)
- Vercel (free)

The deployed site must:

- Load without errors
- Be responsive on mobile and desktop
- Have all features working

---

## 🎤 Portfolio Presentation

Prepare a **portfolio presentation** that includes:

- Project title and business description
- Live demo (show the deployed website)
- Key features explained
- Technical decisions explained (why HTML structure, why Flexbox/Grid, why certain JavaScript patterns)
- Challenges faced and how you solved them
- What you would improve next

Format options:

- Written document (PDF or Markdown)
- Video recording (3–5 minutes)
- Live presentation (if applicable)

---

## 🗣️ Project Defense

You must be able to **defend your project** by answering questions such as:

- Why did you use semantic HTML here?
- Why did you choose Flexbox for this section?
- Why did you use Grid for the gallery?
- Why is this validation not a security boundary?
- What happens when the API fails?
- How did you debug this problem?
- Why did you use localStorage?
- What accessibility problem did you find?
- How did you improve performance?
- How did you protect against unsafe DOM insertion?
- Why is this commit separated from the previous commit?
- What would you improve if you had another week?
