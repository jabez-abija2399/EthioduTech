<Context>
Programs rarely do the exact same thing every time they run. If a user is logged in, show their profile. If they aren't, show a login screen. We use Conditionals to branch our code based on true/false questions.
</Context>

<Objective>
By the end of this lesson, you will control program flow by executing different code paths using if/else statements.
</Objective>

<Concept>
## The `if / else` Statement
An `if` statement looks at a condition (which must evaluate to `true` or `false`). If it's true, it runs a block of code. If it's false, it skips it (or runs an `else` block instead).

```javascript
let temperature = 30;

if (temperature > 75) {
  // This code runs ONLY if the condition is true
  console.log("It is hot outside!");
} else {
  // This code runs ONLY if the condition is false
  console.log("It is cold outside!");
}
```

## The `else if` Statement
You can chain multiple decisions together!
```javascript
if (score === 100) {
  console.log("Perfect!");
} else if (score > 50) {
  console.log("You passed!");
} else {
  console.log("Try again.");
}
```
The computer checks them in order, top to bottom. As soon as it finds *one* true condition, it runs that block and completely skips the rest!
</Concept>

<InteractiveSandbox type="debugging_challenge">
A developer wrote this code to check a user's age. The user is 15. The program should output "You are a teenager", but instead it outputs "You are a child". 

```javascript
let age = 15;

if (age < 18) {
  console.log("You are a child");
} else if (age >= 13) {
  console.log("You are a teenager");
}
```
What is wrong with the logic?
</InteractiveSandbox>

<HintLadder>
- Level 1: Remember, the computer checks from top to bottom, and stops as soon as it finds a true condition.
- Level 2: Is 15 less than 18? Yes. So the first block runs.
- Level 3: The order is wrong! The computer never even checks the second condition because the first one was true. They need to check for the teenager condition first, or change their logic.
</HintLadder>

</Reflection>
