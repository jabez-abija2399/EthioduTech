<Context>
Arrays are perfect for ordered lists (like a list of scores). But what if you need to represent a single, complex entity—like a User? A User has a name, an email, and an age. If you put those in an array `["Alice", "alice@email.com", 25]`, you have to memorize that index 1 is the email. There is a much better way.
</Context>

<Objective>
By the end of this lesson, you will model complex entities using JavaScript objects with key-value pairs.
</Objective>

<Concept>
## Creating an Object
An **Object** is a collection of named properties (called **key-value pairs**). We create objects using curly braces `{ }`.

```javascript
let user = {
  name: "Alice",        // 'name' is the key, "Alice" is the value
  email: "alice@test",
  age: 25,
  isActive: true
};
```

## Accessing and Updating Properties
Instead of using a numbered index, you access object data using **dot notation**.

```javascript
// Read a value
console.log(user.name); // Outputs: "Alice"

// Update a value
user.age = 26; 

// Add a brand new property!
user.role = "Admin";
```

### Arrays vs Objects
- Use an **Array** when the *order* matters (e.g., Top 10 high scores).
- Use an **Object** when the *labels/names* matter (e.g., A specific product's price, title, and description).
</Concept>

<Reflection>
Objects allow us to group related data together. By bundling a name, an email, and an age into a single `user` object, we can pass that entire object into a function as a single argument!
</Reflection>
