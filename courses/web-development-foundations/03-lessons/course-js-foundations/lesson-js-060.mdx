<Context>
So far, every line of JavaScript you have written executes immediately, one after the other. But what happens if you need to ask a server for data? That request takes time. If JavaScript stopped and waited for the network, your entire web page would freeze.
</Context>

<Objective>
By the end of this lesson, you will explain the concept of asynchronous execution and Promises.
</Objective>

<Concept>
## Synchronous vs. Asynchronous
- **Synchronous**: Code runs in exact order, top to bottom. The next line cannot start until the current line finishes.
- **Asynchronous**: Code starts a task (like a timer or a network request), sets it aside, and continues running the rest of the script immediately. When the background task finishes, the browser notifies your code.

## The Promise
In modern JavaScript, asynchronous tasks return a **Promise**. 
A Promise is an object representing the *eventual* completion (or failure) of an asynchronous operation. 

A Promise can be in one of three states:
1. **Pending**: The task is still running.
2. **Fulfilled (Resolved)**: The task finished successfully and returned data.
3. **Rejected**: The task failed (e.g., the network disconnected).

## Predicting Execution Order
Look at this code:
```javascript
console.log("One");

// fetch() is asynchronous!
fetch('https://api.example.com/data') 
  .then(function(response) {
     console.log("Two");
  });

console.log("Three");
```
Because `fetch` takes time, the browser moves on immediately. The output in the console will be:
`One`
`Three`
`Two` (Whenever the server finally responds)
</Concept>

<InteractiveSandbox type="classification">
A developer writes the following code:
```javascript
console.log("A");
setTimeout(function() {
  console.log("B");
}, 1000); // Waits 1 second
console.log("C");
```
What will be the exact order of letters logged to the console?

A. A, B, C
B. A, C, B
C. C, A, B
</InteractiveSandbox>

<Feedback>
B is correct! "A" logs immediately. The timeout is started, but the browser does not stop. It moves on to log "C" immediately. One second later, the timeout finishes and "B" is logged.
</Feedback>
