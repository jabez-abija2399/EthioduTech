<Context>
Right now, your JavaScript runs instantly when the page loads. Real interactivity requires waiting for a user to *do* something—like clicking a button or typing in an input.
</Context>

<Objective>
By the end of this lesson, you will attach event listeners to UI elements to respond to user interactions.
</Objective>

<Concept>
## Listening for Events
To make an element interactive, we attach an "event listener". 
The `addEventListener` method takes two arguments:
1. The name of the event (e.g., `'click'`, `'mouseover'`, `'keydown'`).
2. A function to run when the event happens (often called a "callback" function).

Example:
```javascript
const button = document.querySelector('#submit-btn');

function handleClick() {
  console.log("The button was clicked!");
}

button.addEventListener('click', handleClick);
```

*Note: We pass `handleClick`, not `handleClick()`. We want the browser to run the function LATER when the click happens, not right now!*

## Anonymous Functions
You will often see developers write the function directly inside the event listener. This is called an anonymous function:
```javascript
button.addEventListener('click', function() {
  document.body.classList.toggle('dark-mode');
});
```
</Concept>

<Reflection>
Events are the heartbeat of the modern web. Every time you click, swipe, or type on a website, an event listener is running a JavaScript function in the background.
</Reflection>
