<Context>
Network requests fail. The server might be down, the user might lose their internet connection, or you might misspell the URL. If you don't anticipate and handle these errors, your app will break silently and leave the user staring at an empty screen.
</Context>

<Objective>
By the end of this lesson, you will implement error handling for failed network requests.
</Objective>

<Concept>
## Catching Promise Rejections
If a Promise fails (is "rejected"), it skips all the `.then()` blocks and looks for a `.catch()` block at the end of the chain.

```javascript
fetch('https://invalid-url.com/data')
  .then(function(response) {
    return response.json();
  })
  .then(function(data) {
    console.log(data);
  })
  .catch(function(error) {
    console.error("A network error occurred:", error);
    // You should also update the DOM here to show the user a friendly error message!
  });
```

## Handling HTTP Errors
`fetch()` only rejects a Promise if the network *physically fails* (like being offline). 
If the server is online but returns a `404 Not Found` error, `fetch()` still considers that a "successful" connection! 

To handle 404s or 500s, you must manually check the `response.ok` property before parsing the JSON:

```javascript
fetch('https://jsonplaceholder.typicode.com/users/999') // User 999 does not exist!
  .then(function(response) {
    if (!response.ok) {
      throw new Error("Server returned status: " + response.status);
    }
    return response.json();
  })
  // ... .then() ...
  .catch(function(error) {
    console.error("Caught an error:", error);
  });
```
By using `throw new Error()`, we force the code to jump straight to the `.catch()` block.
</Concept>
