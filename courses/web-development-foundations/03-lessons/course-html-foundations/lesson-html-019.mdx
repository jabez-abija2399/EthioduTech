<Context>
Now that you know how to spot accessibility problems, it's time to fix them.
</Context>

<Objective>
By the end of this lesson, you will fix common structural accessibility violations to pass a basic audit.
</Objective>

<Concept>
## Repairing HTML
When repairing HTML, we don't just change things randomly. We:
1. Identify the symptom (e.g., "The screen reader just says 'image'").
2. Identify the problem (e.g., "Missing alt text").
3. Apply the structural fix (e.g., Add `alt="A red sports car"`).
4. Explain the impact (e.g., "This provides alternative text for the meaningful image").
</Concept>

<InteractiveSandbox type="repair">
Fix the following HTML. The image is a photo of the team, and the form label is currently broken.
```html
<section>
  <img src="team.jpg">
  <form>
    <label>Join our Newsletter</label>
    <input type="email" id="email-signup">
    <button type="submit">Join</button>
  </form>
</section>
```
</InteractiveSandbox>

<Feedback>
To fix this, you must add `alt="Photo of our team"` to the `<img>` tag, and add `for="email-signup"` to the `<label>` tag.
</Feedback>

<IndependentPractice>
Repair this layout. It currently uses generic boxes. Change the generic tags to meaningful semantic landmarks (`header`, `main`, `footer`).
```html
<div class="header">
  <h1>My Blog</h1>
</div>
<div class="content">
  <article>Post 1</article>
</div>
<div class="footer">
  <p>Bye!</p>
</div>
```
</IndependentPractice>

<Reflection>
By fixing the semantics, you've improved the structural blueprint of the page!
</Reflection>
