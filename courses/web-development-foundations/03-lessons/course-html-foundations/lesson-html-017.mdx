<Context>
In the previous lesson, we learned that a form needs an input. But an input by itself doesn't tell the user what to type, and it doesn't give the browser a way to send the data.
</Context>

<Objective>
By the end of this lesson, you will link labels to inputs and implement a submit button.
</Objective>

<Concept>
## Labels and Submission

### Labels
A `<label>` explains the purpose of an input. To link a label to an input, the `for` attribute on the label must exactly match the `id` attribute on the input.

```html
<label for="user-email">Email Address</label>
<input type="email" id="user-email" name="email">
```

### Submission
Forms also need a way to submit data. This is done using a button with `type="submit"`.
When this button is clicked, the browser gathers the data from the inputs (using their `name` attributes) and tries to send it to a server. 

*(Note: In this HTML course, we are only building the structure. A backend application is required to actually process the data.)*
</Concept>

<InteractiveSandbox type="code_completion">
Link the label to the input, and add a submit button.
```html
<form>
  <label ___="newsletter">Subscribe:</label>
  <input type="email" ___="newsletter" name="email">
  
  <button type="___">Sign Up</button>
</form>
```
</InteractiveSandbox>

<Feedback>
The label uses `for="newsletter"` to link to the input's `id="newsletter"`. The button must be `type="submit"`.
</Feedback>

<IndependentPractice>
Write a complete form that asks for a user's "First Name". Include a properly linked label, a text input with the name attribute "firstName", and a submit button.
</IndependentPractice>

<Reflection>
Properly linked labels ensure that users on screen readers know exactly what the input is asking for when they focus on it!
</Reflection>
