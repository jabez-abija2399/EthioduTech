<Context>
Up to this point, you have been writing isolated pieces of HTML. But real websites consist of multiple pages linked together. Before writing the code, developers plan the architecture.
</Context>

<Objective>
By the end of this lesson, you will plan the structure and paths for a multi-page website.
</Objective>

<Concept>
## Information Architecture
When planning a multi-page site, consider:
1. **Pages**: What files do you need? (e.g., `index.html`, `about.html`, `contact.html`).
2. **Navigation**: How will the user get from one page to another? (A `<nav>` block shared across pages).
3. **File Paths**: Where do the files live? If they are all in the same folder, relative paths like `href="about.html"` work perfectly.
</Concept>

<InteractiveSandbox type="planning">
You are building a Recipe Website. You need a homepage, a page for Desserts, and a page for a specific Brownie recipe.
Plan the file names and structure.
</InteractiveSandbox>

<HintLadder>
- Level 1: What should the homepage always be named?
- Level 2: The homepage is `index.html`.
- Level 3: A simple structure: `index.html`, `desserts.html`, and `brownies.html` in the same folder.
</HintLadder>

<Reflection>
Planning saves you from rewriting hundreds of broken links later. Always map out your files before you type your first `<!DOCTYPE>`!
</Reflection>
