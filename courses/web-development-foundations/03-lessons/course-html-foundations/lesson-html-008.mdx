<Context>
Browsers try to be helpful. If you make a mistake in your HTML, the browser will often try to fix it for you silently. However, invalid HTML can cause severe layout or accessibility bugs later.
</Context>

<Objective>
By the end of this lesson, you will verify an HTML document passes validation and fix basic structural errors.
</Objective>

<Concept>
## Why Validate?
To ensure our code works perfectly across all browsers (and for users utilizing screen readers), we run our code through a tool called an HTML Validator.
A Validator checks if tags are opened and closed correctly, and if they are nested in the proper order.
</Concept>

<InteractiveSandbox type="debugging_challenge">
Find the structural error in this skeleton:
```html
<!DOCTYPE html>
<html>
  <head>
    <title>Invalid Page
  </head>
  <body>
    Hello!
  </body>
</html>
```
</InteractiveSandbox>

<HintLadder>
- Level 1: Look closely at the `<head>` section.
- Level 2: Tags must be opened and closed.
- Level 3: The `<title>` tag was never closed. It should be `</title>`.
</HintLadder>

<IndependentPractice>
Examine this code:
```html
<html>
<!DOCTYPE html>
  <body>
    <head><title>Test</title></head>
  </body>
</html>
```
Identify the two major structural ordering errors.
</IndependentPractice>

Validating early saves hours of debugging CSS later!
