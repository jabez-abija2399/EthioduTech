<Context>
In previous lessons, we structured text using headings, paragraphs, and lists. But what about the overall layout of the page itself? We need tags to define the main regions of our site.
</Context>

<Objective>
By the end of this lesson, you will build a semantically structured HTML document using header, main, article, and nav tags.
</Objective>

<Concept>
## Semantic Landmarks
Semantic HTML means using tags that clearly describe their purpose. A browser can't tell what a plain generic box (`<div>`) is supposed to be. But it *does* know what these are:

- **`<header>`**: The top section of a page or article (usually contains a logo or main title).
- **`<nav>`**: A section containing navigation links.
- **`<main>`**: The dominant content of the page. There should only be one `<main>` per page.
- **`<article>`**: A self-contained composition (like a blog post or news story).
- **`<footer>`**: The bottom section of a page.

Using these tags helps screen readers skip straight to the `<main>` content or the `<nav>` menu instantly!
</Concept>

<InteractiveSandbox type="repair">
A developer used generic boxes (`<div>`) for everything. Fix the structure by replacing the `<div>` tags with appropriate semantic landmarks: `<header>`, `<main>`, and `<footer>`.
```html
<body>
  <div id="top-bar">
    <h1>My Website</h1>
  </div>
  <div id="content">
    <p>Welcome to my site.</p>
  </div>
  <div id="bottom-bar">
    <p>Copyright 2024</p>
  </div>
</body>
```
</InteractiveSandbox>

<Feedback>
The `#top-bar` should be a `<header>`. The `#content` should be a `<main>`. The `#bottom-bar` should be a `<footer>`. 
</Feedback>

<Reflection>
Semantic HTML does not automatically style your page or guarantee 100% accessibility, but it gives your content a meaningful blueprint that browsers and assistive technologies can understand!
</Reflection>
