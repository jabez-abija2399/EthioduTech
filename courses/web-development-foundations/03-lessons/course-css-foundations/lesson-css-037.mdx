<Context>
Before writing hundreds of lines of CSS, professional developers stop and plan. A responsive interface is not built by randomly adding media queries until it looks acceptable. It is built by answering specific questions about the content and the layout.
</Context>

<Objective>
By the end of this lesson, you will plan the layout transitions for a responsive webpage design.
</Objective>

<Concept>
## The Responsive Planning Workflow
When looking at a design brief or a semantic HTML document, ask yourself these questions before writing CSS:

1. **Content Structure**: What are the major sections? (e.g., Header, Main Content, Sidebar, Footer).
2. **Layout Strategy**: Does this require Flexbox (1-dimensional flow) or Grid (2-dimensional placement)?
3. **Fluid Dimensions**: Which elements should shrink and grow fluidly (using `%`, `vw`, or `1fr`), and which elements should remain fixed?
4. **Responsive Conditions**: At what point does the content become too squeezed to read comfortably? *This is your breakpoint.*
5. **Layout Shifts**: When the screen is too narrow, what should happen? Should a grid drop from 3 columns to 1 column? Should a horizontal flex row wrap into a vertical stack?

### Breakpoints respond to Content, not Devices
Do not think in terms of "mobile", "tablet", and "desktop" pixels (e.g., 320px, 768px, 1024px). Think in terms of the content. If a row of three cards becomes unreadable at 850px, then 850px is the correct breakpoint for that specific design!
</Concept>

<InteractiveSandbox type="classification">
Look at the following design requirement:
"The navigation bar has a logo on the far left, and five links on the far right."

Which layout model is the most appropriate choice for this specific component?
- A. CSS Grid with 6 defined columns
- B. Flexbox with `justify-content: space-between`
- C. Normal Document Flow with `text-align: right`
</InteractiveSandbox>

<Feedback>
B is the correct choice! The navigation bar is a single row (1-dimensional), making Flexbox perfect for pushing the logo and links to opposite ends using `space-between`.
</Feedback>

<IndependentPractice>
You are planning a "Team Directory" page. The HTML consists of a `<header>`, a `<main>` container holding 12 `<article>` employee profiles, and a `<footer>`. 

Answer the following planning questions:
1. Which layout model (Flexbox or Grid) is best for arranging the 12 employee profiles?
2. If the profiles are arranged in 3 columns on a wide screen, what layout shift should happen when the screen becomes very narrow?
</IndependentPractice>

<HintLadder>
- Level 1: Think about the 12 profiles. Are they arranged in both rows and columns simultaneously?
- Level 2: Yes, Grid is ideal for the 12 profiles.
- Level 3: On a narrow screen, 3 columns will squish the text. The layout shift should be dropping the Grid from 3 columns down to 1 column.
</HintLadder>

<Reflection>
Planning saves hours of debugging. If you know exactly how the layout should behave before you write a single line of CSS, the implementation becomes merely translating your decisions into syntax!
</Reflection>
