<Context>
If you set an image to be exactly `width: 800px`, what happens on a phone that is only 400px wide? The image spills off the screen, causing a terrible horizontal scrollbar! Fixed units are dangerous in a responsive world.
</Context>

<Objective>
By the end of this lesson, you will implement fluid sizing using relative units (%, vh, vw, rem).
</Objective>

<Concept>
## Relative Units
Instead of using fixed pixels (`px`), modern CSS relies heavily on units that adapt to their surroundings:

- **Percentage (`%`)**: Sized relative to the parent container. `width: 50%` means half as wide as whatever box it is sitting inside.
- **Viewport Width (`vw`) & Height (`vh`)**: Sized relative to the entire browser window. `100vw` means exactly the full width of the screen. `50vh` means exactly half the height of the screen.
- **`rem` (Root em)**: Sized relative to the default font size of the browser (usually 16px). `2rem` equals roughly 32px. Using `rem` for typography ensures your text scales if a visually impaired user increases their browser's default font size!

```css
.hero-image {
  /* The image will shrink to fit the parent container, but never grow past 100% */
  max-width: 100%; 
}
```
</Concept>

<InteractiveSandbox type="repair">
A developer built a header section. On a laptop, it looks fine. On a phone, it forces the user to scroll horizontally because of a fixed width. Change the CSS to use a relative percentage unit so it fits the screen automatically.

```css
.header-box {
  width: 1000px; /* <-- This breaks on mobile! */
  background-color: darkblue;
}
```
</InteractiveSandbox>

<HintLadder>
- Level 1: What unit is the developer using right now?
- Level 2: They are using fixed pixels (`px`).
- Level 3: Change `1000px` to `100%` so the box is always exactly as wide as its container, regardless of screen size.
</HintLadder>

<Reflection>
Pixels are rigid. The web is fluid. By using percentages, `vh/`vw`, and `rem`, you allow the browser to do the math and scale your designs safely!
</Reflection>
