<Context>
What happens if you tell a paragraph to be blue using a Type Selector, but tell it to be red using an ID selector? Who wins? Welcome to the Cascade.
</Context>

<Objective>
By the end of this lesson, you will predict which CSS rule will apply based on specificity and the cascade.
</Objective>

<Concept>
## Specificity and The Cascade
CSS resolves conflicting rules using a system called the Cascade. If two rules target the exact same element and set the exact same property (like `color`), the browser uses **Specificity** to decide the winner.

The general hierarchy of specificity (from weakest to strongest) is:
1. **Type Selectors** (`p`, `h1`) are weak.
2. **Class Selectors** (`.highlight`, `.nav-link`) are stronger.
3. **ID Selectors** (`#main-title`) are the strongest.

If specificity is an exact tie (e.g., two class selectors target the same element), the rule written **last** in the CSS file wins.
</Concept>

<InteractiveSandbox type="prediction">
Given this code, what color will the `h1` text be, and why?
```html
<h1 id="brand" class="header-text">My Website</h1>
```
```css
h1 { color: black; }
.header-text { color: green; }
#brand { color: purple; }
```
</InteractiveSandbox>

<HintLadder>
- Level 1: Are there conflicting rules trying to change the color?
- Level 2: Yes, a Type, Class, and ID selector are all targeting the `h1`.
- Level 3: Which selector has the highest specificity?
- Level 4: The ID selector is the strongest, so the text will be purple.
</HintLadder>

<IndependentPractice>
Read the following CSS. Both rules target the same element, but the specificity is tied (both are classes). Which rule wins?
```css

.warning { color: orange; }
```
</IndependentPractice>

<Reflection>
Understanding the Cascade means you don't have to guess why your styles aren't working. When a style doesn't apply, it's almost always because a more specific selector is overriding it!
</Reflection>
