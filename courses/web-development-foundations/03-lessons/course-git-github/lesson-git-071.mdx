<Context>
You created a branch, worked safely, and successfully built a new feature. But currently, that feature only exists in its parallel universe. How do you bring that feature back into the main project? You must **merge** the branch.
</Context>

<Objective>
By the end of this lesson, you will merge a feature branch into the main branch locally.
</Objective>

<Concept>
## The Merging Mental Model
Merging combines the history of two branches.
To merge a branch:
1. You must first switch (`checkout`) to the branch that is RECEIVING the changes (usually `main`).
2. You tell Git to merge the specific feature branch INTO your current branch.

## The Merge Command
If you want to bring the work from a branch called `new-header` into `main`, the exact workflow looks like this:

```bash
# 1. Switch to the receiving branch
git checkout main

# 2. Merge the feature branch into the current branch
git merge new-header
```
Git will fast-forward your `main` branch, instantly pulling in all the commits you made on `new-header`. Your main universe now has the completed feature!
</Concept>

<InteractiveSandbox type="terminal_debugging">
A developer finished working on a branch called `footer-fix`. They want to merge it into `main`.
They are currently on the `footer-fix` branch. They ran:

```bash
git merge main
```
This was the exact opposite of what they intended! They merged the main branch *into* the feature branch. 
How should they have done this?
</InteractiveSandbox>

<HintLadder>
- Level 1: What branch should you be standing on when you want to receive changes?
- Level 2: You must stand on the branch you want to update.
- Level 3: They should have run `git checkout main` first, and THEN run `git merge footer-fix`.
</HintLadder>

<IndependentPractice>
1. Open your terminal and create a new branch called `test-merge`.
2. On that branch, create a new file called `merge.txt` and commit it.
3. Switch back to your `main` branch. (Verify the file is missing!)
4. Merge the `test-merge` branch into `main`.
5. Check your folder. The file should now be present on `main`!
</IndependentPractice>

<Reflection>
Merging is how teams integrate work. One developer builds the header on their branch, another builds the footer on their branch, and both are merged back into `main` when they are perfectly ready!
</Reflection>
