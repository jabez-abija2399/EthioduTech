<Context>
What happens if two developers edit the exact same line of the exact same file on two different branches? When they try to merge, Git won't know which edit to keep. This is called a **Merge Conflict**. Don't panic! Conflicts are a normal part of development.
</Context>

<Objective>
By the end of this lesson, you will identify and resolve simple merge conflicts.
</Objective>

<Concept>
## Identifying a Conflict
When you run `git merge` and a conflict occurs, Git will output:
`CONFLICT (content): Merge conflict in index.html`
`Automatic merge failed; fix conflicts and then commit the result.`

If you open the conflicted file, Git has deliberately injected "Conflict Markers" to show you both versions:

```html
<<<<<<< HEAD
<h1>Welcome to our Website</h1>
=======
<h1>Welcome to our Awesome Store</h1>
>>>>>>> feature-branch
```

## Resolving the Conflict
To resolve the conflict, you must manually edit the file.
1. Decide which code you want to keep (or combine them!).
2. **Delete the conflict markers** (`<<<<<<<`, `=======`, and `>>>>>>>`).
3. Save the file.

Once you have fixed all conflicting files, you tell Git the conflict is resolved by staging and committing the result:
```bash
git add index.html
git commit -m "Resolve merge conflict in index.html"
```

## Safety Valve: Aborting a Merge
If you panic, get confused, or completely break the file while trying to resolve the conflict, you can safely cancel the entire merge and return to exactly how your files looked before you typed `git merge`. Just run:
```bash
git merge --abort
```
</Concept>

<InteractiveSandbox type="terminal_debugging">
You are merging a branch, and Git alerts you to a conflict in `app.js`.
You open `app.js` and see this:

```javascript
<<<<<<< HEAD
let maxUsers = 100;
=======
let maxUsers = 500;
>>>>>>> update-limits
```
You decide the limit should be `500`. Rewrite the file exactly as it should look when the conflict is resolved.
</InteractiveSandbox>

<Feedback>
The file should simply say:
```javascript
let maxUsers = 500;
```
All markers must be removed!
</Feedback>

<IndependentPractice>
You will intentionally cause a conflict:
1. On `main`, edit line 1 of `test.txt` to say "Apple" and commit.
2. Create and checkout a branch called `conflict-test`.
3. Change line 1 of `test.txt` to say "Banana" and commit.
4. Switch back to `main`.
5. Run `git merge conflict-test`. You will get a conflict!
6. Open the file, resolve it so it says "Apple and Banana", remove the markers, save, and commit.
</IndependentPractice>

<Reflection>
A merge conflict is not an error; it is a safety feature! Git is pausing the merge to say, "I am a robot, I don't know what you want. Please make the final decision."
</Reflection>
