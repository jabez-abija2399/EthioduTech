<Context>
Your code is tested, documented, and pushed to GitHub. But code that only lives in a repository is hard to share with non-developers (like recruiters or clients). The final step is to deploy your project live to the internet so anyone can view it, and then reflect on what you have learned.
</Context>

<Objective>
By the end of this lesson, you will deploy the project live and write a reflective summary of technical decisions.
</Objective>

<Concept>
## 1. Deployment (GitHub Pages)
Since your project consists only of static files (HTML, CSS, Vanilla JavaScript), it is incredibly easy to host for free. GitHub Pages allows you to serve your repository directly to the web.
When you enable GitHub Pages in your repository settings, GitHub automatically generates a live URL (e.g., `https://yourusername.github.io/my-capstone/`).

## 2. Technical Reflection
Every time you finish a project, you should conduct a "post-mortem" or reflection. Developers do this to ensure they learn from their mistakes.
A good reflection answers:
- **What worked?** What parts of the project went smoothly?
- **What was difficult?** What bugs took hours to solve?
- **What did you learn?** How did this project change your understanding of web development?
- **What would you improve?** If you had another month, what would you add or rewrite?

## 3. Presenting Your Work
If you are asked about this project in an interview, do not just list the technologies used. Tell the *story* of the project.
"I wanted to solve X problem. I decided to use CSS Grid for the layout because Y. I ran into a bug with JavaScript event listeners, but I solved it by doing Z."
</Concept>

<InteractiveSandbox type="classification">
Which of the following statements is a strong, professional reflection of a technical challenge?

A. "JavaScript is really hard and I hated it."
B. "I had a bug where the button didn't work. I fixed it."
C. "I struggled with managing the state when multiple items were deleted. I initially tried to manually remove the HTML elements, but I learned it was much more reliable to update the JavaScript array first and then re-render the list."
D. "My website is perfect and has no bugs."
</InteractiveSandbox>

<Feedback>
C is the correct choice! It clearly identifies the problem, explains the initial (incorrect) approach, and highlights the specific technical lesson learned.
</Feedback>

<IndependentPractice>
1. **Deploy**: Go to your project repository on GitHub. Navigate to Settings -> Pages. Select your `main` branch as the source and click Save. Wait a few minutes and visit your live URL!
2. **Reflect**: Create a new file in your repository called `REFLECTION.md`.
3. Write a 2-3 paragraph reflection answering the questions from the Concept section above. Be specific about a bug you had to debug!
4. **Update README**: Add the live GitHub Pages URL to the very top of your `README.md`.
5. **Final Push**: Commit `REFLECTION.md` and your updated `README.md`, and push them to GitHub.
</IndependentPractice>
