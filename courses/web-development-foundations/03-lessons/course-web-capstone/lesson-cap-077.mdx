<Context>
You have a beautiful, responsive HTML and CSS interface. But right now, it is entirely static. Nothing happens when a user clicks your buttons. It is time to bring your project to life using JavaScript.
</Context>

<Objective>
By the end of this lesson, you will implement JavaScript logic, event handling, and data fetching for the capstone.
</Objective>

<Concept>
## 1. Select and Listen
The core pattern for interactivity is:
1. Select an element using `document.querySelector`.
2. Add an event listener to that element using `addEventListener`.
3. Run a function when the event occurs.

## 2. Update the State, Then Update the UI
When a user interacts with your app, do not try to manually update every single HTML element one by one. Instead:
1. Update your JavaScript data (your "state").
2. Write a single function called `render()` or `updateUI()` that looks at the state and draws the correct HTML on the screen.

## 3. Fetching External Data (If Applicable)
If your requirements involve external data (like weather or a random quote), you will use the `fetch()` API. Remember to handle errors gracefully! What should your UI look like if the network is disconnected?
</Concept>

In the `script.js` file, select this button and add an event listener. When clicked, it should toggle the class `dark-mode` on the `<body>` element.

<HintLadder>
- Level 1: How do you select an element by its ID?
- Level 2: Use `const btn = document.getElementById('theme-btn');` or `document.querySelector('#theme-btn');`.
- Level 3: Use `btn.addEventListener('click', function() { ... })`
- Level 4: Inside the function, use `document.body.classList.toggle('dark-mode');`
</HintLadder>

<IndependentPractice>
This is the behavior phase of your project.
1. Create your `script.js` file and link it to your HTML.
2. Select the necessary DOM elements.
3. Write the functions that change your application's state.
4. Write the event listeners that trigger those functions.
5. If your project uses `fetch`, implement the network calls now.
6. **Git Workflow**: Do not write 500 lines of JavaScript before committing. Commit each feature separately! (e.g., `git commit -m "Add event listener for form submission"`).
</IndependentPractice>

<Reflection>
Debugging JavaScript can be frustrating. Remember the developer loop: reproduce the problem, form a hypothesis, test it with `console.log`, and verify the fix. You are not guessing; you are investigating!
</Reflection>
