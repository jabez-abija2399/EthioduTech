# Pedagogy Research

## Active Learning
- **Practical meaning:** Students must be "doing" rather than just "reading" or "watching".
- **How it should appear:** Every lesson concept must immediately be followed by a micro-challenge in the interactive workspace.
- **What it should NOT become:** Mindless typing of exact copy-pasted code without understanding.

## Retrieval Practice
- **Practical meaning:** Forcing the brain to recall information strengthens memory.
- **How it should appear:** Quizzes and mini-challenges that ask students to write syntax from memory without looking at the reference.
- **What it should NOT become:** Punitive tests that block progress indefinitely.

## Spaced Practice
- **Practical meaning:** Reviewing concepts over time rather than cramming.
- **How it should appear:** HTML tags taught in Course 2 must be required to build projects in Course 3 and Course 4.
- **What it should NOT become:** Irrelevant interruptions in the middle of learning a new, unrelated concept.

## Varied Practice
- **Practical meaning:** Applying the same skill in different contexts.
- **How it should appear:** Teaching `flexbox` by building a navbar, then later retrieving `flexbox` to build a photo gallery grid.
- **What it should NOT become:** Changing the toolchain constantly (e.g., switching between 5 different CSS frameworks).

## Gradual Release of Support (Scaffolding)
- **Practical meaning:** "I do, we do, you do."
- **How it should appear:** 
  1. Micro Project: Step-by-step instructions.
  2. Guided Project: High-level instructions with hints.
  3. Module Project: Requirements only.
  4. Capstone: Independent creation.
- **What it should NOT become:** Dropping a student into an empty IDE in Course 1 with no guidance.

## Debugging and Problem Solving
- **Practical meaning:** The ability to fix broken code is as important as writing new code.
- **How it should appear:** Specific "Broken Code" lessons where the objective is to use DevTools to find the error, not write the feature.
- **What it should NOT become:** Accidental, frustrating bugs caused by platform errors rather than intentional pedagogical design.

## Project-Based Learning
- **Practical meaning:** Learning driven by the desire to build a tangible artifact.
- **How it should appear:** The entire Path culminates in a Capstone project. Each course culminates in a Module project.
- **What it should NOT become:** Painting-by-numbers where every student's project looks identical.
